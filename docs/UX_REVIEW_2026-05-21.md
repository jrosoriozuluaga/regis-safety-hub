# UX Review -- Regis SG-SST Platform

**Date:** 2026-05-21
**Reviewer:** Senior UX Design Audit
**Scope:** All 22 page files + 2 layout components
**Criteria:** Visual hierarchy, cognitive load, empty/error/loading states, mobile touch targets, contrast/legibility, microcopy, critical flows, cross-module consistency

---

## Executive Summary

The Regis SG-SST platform demonstrates solid foundational UX architecture: a consistent sidebar navigation, well-structured card-based layouts, and effective use of the shadcn/ui component library create a coherent baseline across most modules. The PILA module stands out as the most polished workflow, with clear status progression, contextual actions per record state, and integrated multi-channel reminders. Public-facing pages (Login, ForgotPassword, UploadPila) show strong brand alignment and appropriate state management. The platform successfully handles complex Colombian regulatory domain concepts (Resolution 0312, PHVA cycles, GTC 45 risk matrices) without overwhelming the user, which is a meaningful achievement for a B2B compliance tool.

However, several systemic UX gaps reduce the platform's production readiness and professional polish. No page implements skeleton loading states -- every data-dependent view shows a single centered spinner, which creates perceived slowness and layout shift when content renders. No table implements pagination or virtual scrolling; ActivityLog loads 200 records and Companies/Workers load entire datasets, which will degrade both performance and usability as client count scales toward the target of 90+ companies. Empty states vary wildly in quality: Documents and EquipmentInventory provide icon + message + call-to-action, while most other pages show plain text strings with no visual hierarchy or guidance. The NotFound page is entirely in English, breaking the Spanish-language contract of the application. Multiple page titles and labels are missing required Spanish diacritical marks (tildes), which appears unprofessional to native speakers.

Cross-module inconsistencies compound these issues. Two distinct toast notification systems coexist (sonner vs useToast hook in EmailTemplates). Two pages (Calendar, CompanyReport) bypass the standardized PageHeader component. Data fetching strategies diverge between react-query and raw useEffect patterns. The company selector -- used in roughly 10 pages -- is reimplemented each time rather than abstracted into a shared component. Badge text renders at 10px and calendar events at 9px, both below accessibility thresholds. Icon-only action buttons (size="icon") render at 36x36px, below the recommended 44x44px mobile touch target. Addressing the top 10 findings below would dramatically improve perceived quality, accessibility compliance, and the platform's readiness for the competition demo.

## Top 10 Highest ROI Improvements

Ranked by impact-to-effort ratio. Each item addresses a systemic issue affecting multiple pages.

### 1. Add Pagination to All Tables
- **Impact:** High -- prevents performance degradation at scale (90+ companies target), improves scannability
- **Effort:** Medium -- create a reusable `<PaginatedTable>` wrapper component
- **Pages affected:** Pila, Companies, Workers, Users, ActivityLog, Documents, EquipmentInventory (7 pages)
- **Implementation:** Create `src/components/common/PaginatedTable.tsx` wrapping shadcn Table with page size selector (25/50/100) and page navigation. Use Supabase `.range()` for server-side pagination.

### 2. Standardize Loading States with Skeletons
- **Impact:** High -- eliminates perceived slowness, prevents layout shift, adds professional polish
- **Effort:** Low -- shadcn has a `<Skeleton>` component ready to use
- **Pages affected:** All 22 pages
- **Implementation:** Replace `<Loader2 className="animate-spin" />` patterns with contextual skeletons matching the expected layout. Create `<TableSkeleton rows={5} cols={6} />` and `<KpiCardSkeleton />` reusable components.

### 3. Fix All Missing Tildes/Accents
- **Impact:** High -- unprofessional appearance for native Spanish speakers, competition judges will notice
- **Effort:** Very Low -- string replacements only
- **Pages affected:** Settings ("Configuracion"/"Parametros"), MedicalExams ("Examenes"/"busqueda"), Committees ("comite"/"reunion"), Calendar, and various labels
- **Fixes:** "Configuracion" -> with accent, "Parametros" -> with accent, "Examenes" -> with accent, "comite" -> with accent, "reunion" -> with accent, "accion" -> with accent, "busqueda" -> with accent

### 4. Translate NotFound.tsx to Spanish + Add Branding
- **Impact:** High -- currently the only English page in a Spanish app; jarring for users and demo
- **Effort:** Very Low -- 10 minutes
- **Implementation:** Replace "Oops! Page not found" with "Pagina no encontrada", "Return to Home" with "Volver al inicio". Add Regis logo. Match the visual style of Login/ForgotPassword pages.

### 5. Unify Toast Notification System
- **Impact:** Medium -- eliminates UX inconsistency, reduces bundle size
- **Effort:** Very Low -- migrate ~5 calls in EmailTemplates.tsx
- **Implementation:** Replace `useToast()` import with `import { toast } from "sonner"` in EmailTemplates.tsx. Remove unused `useToast` hook if no other consumers.

### 6. Enforce PageHeader on All Pages
- **Impact:** Medium -- visual consistency across the entire app
- **Effort:** Very Low -- 2 file changes
- **Pages affected:** Calendar.tsx, CompanyReport.tsx
- **Implementation:** Replace custom `<h1>` elements with `<PageHeader title="..." description="..." />` matching the pattern used in all other pages.

### 7. Add Tooltips to All Icon-Only Buttons
- **Impact:** Medium -- improves discoverability, accessibility, and reduces user confusion
- **Effort:** Low -- wrap existing buttons in `<Tooltip>` components
- **Pages affected:** Pila, Documents, EquipmentInventory, Companies, Workers, Users, ActivityLog (all pages with action buttons)
- **Implementation:** Create a `<TooltipIconButton>` wrapper: `<Tooltip><TooltipTrigger asChild><Button size="icon">...</Button></TooltipTrigger><TooltipContent>{label}</TooltipContent></Tooltip>`

### 8. Abstract Company Selector into Shared Component
- **Impact:** Medium -- reduces code duplication (~10 pages), ensures consistent behavior
- **Effort:** Medium -- create component, refactor pages
- **Implementation:** Create `src/components/common/CompanySelector.tsx` with standardized empty state, loading state, and value persistence. Use in MedicalExams, RiskMatrices, Committees, EmergencyPlans, Compliance, Documents, EquipmentInventory, Workers, CompanyReport, Pila.

### 9. Improve Empty States Across All Modules
- **Impact:** Medium -- guides users, reduces confusion, looks professional in demos
- **Effort:** Low -- create a reusable `<EmptyState>` component
- **Pages affected:** RiskMatrices, ActivityLog, Calendar, Compliance, Committees (5 pages with weak empty states)
- **Implementation:** Create `src/components/common/EmptyState.tsx` with props: `icon`, `title`, `description`, `actionLabel`, `onAction`. Match the quality of Documents.tsx and Workers.tsx empty states.

### 10. Increase Minimum Text Size for Accessibility
- **Impact:** Medium -- WCAG compliance, legibility on all screens
- **Effort:** Very Low -- CSS class changes
- **Locations:** Badge `text-[10px]` -> `text-xs` (12px), Calendar events `text-[9px]` -> `text-[11px]`, any other sub-12px text
- **Implementation:** Global search for `text-[9px]`, `text-[10px]`, and any font-size below 12px. Replace with `text-xs` minimum.

## General Design Analysis

### Color Palette

- **Primary:** Uses shadcn/ui default theme with blue primary. Adequate for B2B SaaS but generic.
- **Status colors:** Consistent use of semantic colors -- green for success/active, red for destructive/overdue, yellow for warnings, blue for primary actions.
- **Badge colors:** Four variants mapped to action types (default/secondary/destructive/outline) in ActivityLog; consistent.
- **Recommendation:** Consider customizing the primary color to match Regis Colombia brand identity (if a brand color exists beyond the logo). The current default blue is functional but undifferentiated.

### Typography

- **Hierarchy:** Generally well-structured. PageHeader provides consistent H1 treatment. Card titles use appropriate sizing.
- **Issues:**
  - Sub-12px text used in multiple locations (badges at 10px, calendar events at 9px) -- violates accessibility guidelines
  - No consistent treatment of numeric/data text vs. label text
  - Monospace or tabular figures not used for numeric columns in tables, causing visual misalignment
- **Recommendation:** Establish a minimum font size of 12px (`text-xs`). Use `tabular-nums` class on numeric data columns for alignment.

### Spacing

- **Layout padding:** `p-6 lg:p-8` on main content area -- appropriate and consistent.
- **Card spacing:** `space-y-6` between cards on most pages -- consistent.
- **Table density:** Appropriate for data-heavy B2B application. Not too cramped.
- **KPI cards:** Consistent 3-4 card grids across pages, though responsive breakpoints vary.
- **Recommendation:** Standardize KPI grid to `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4` for consistent responsive behavior.

### Component Consistency

| Aspect | Status | Notes |
|--------|--------|-------|
| PageHeader | 20/22 pages | Calendar and CompanyReport diverge |
| Loading states | Consistent (spinner) | But should be skeletons |
| Empty states | Inconsistent | Quality ranges from icon+text+CTA to plain text |
| Delete confirmations | Mostly present | Missing in Committees for sign/archive actions |
| Toast system | Inconsistent | sonner (21 pages) vs useToast (EmailTemplates) |
| Data fetching | Inconsistent | react-query (majority) vs raw useEffect (some) |
| Company selector | Repeated 10x | Not abstracted into shared component |
| Action buttons | Inconsistent | Some have labels, some icon-only without tooltips |
| Print/export | Consistent | Uses shared getExportHeaderHTML utility |
| Form validation | Consistent | Zod on auth pages; inline validation elsewhere |

### Accessibility Observations

- **Touch targets:** Icon-only buttons (`size="icon"`) render at 36x36px -- below the 44x44px WCAG recommendation. Add `className="h-11 w-11"` or use `size="sm"` with icon + text.
- **Color contrast:** shadcn/ui defaults meet WCAG AA for most text. Muted foreground text should be verified against light backgrounds.
- **Focus indicators:** shadcn/ui provides focus-visible rings by default -- adequate.
- **Screen reader support:** Tables use semantic `<th>` via TableHead -- good. However, icon-only buttons lack `aria-label` attributes.
- **Keyboard navigation:** No custom keyboard shortcuts implemented. Tab order follows natural DOM order -- acceptable.
